# Harness Orchestrator tests

`tests/run.sh` first re-runs itself once under `env -i`. The scrubbed run keeps only `HOME` (a fresh temp folder), `TMPDIR`, `LANG=C` and a short `PATH`: `tests/fake-bin`, the folders that hold `jq`, `git` and `bash`, and the system folders. So the tests stay green even when a 0.6.0 launcher has set its own variables or put its `bin/` on `PATH`. Each `t_*.sh` file then runs in its own process and its own temp folder, which is removed afterwards. A file that crashes or checks nothing counts as a failure. The last line is `harness tests: PASS=<n>  FAIL=<m>`.

The engine's own variables use the prefix `HO_`. Tests never call the real `claude`: `tests/fake-bin/claude` comes first on `PATH`. It appends its arguments as one tab-separated line to `$HO_FAKE_CLAUDE_LOG` (default `$HOME/fake-claude.log`), prints `$HO_FAKE_CLAUDE_STDOUT`, and exits with `$HO_FAKE_CLAUDE_EXIT` (default 0). `claude --version` prints `0.0.0 (fake claude)`. `claude auth status` answers like the real CLI: JSON with `"loggedIn": true` and exit 0, or with `HO_FAKE_CLAUDE_LOGGED_OUT=1` `false` and exit 1 (`=lie` prints `false` with exit 0). `tests/fake-bin/codex` logs its arguments to `$HO_FAKE_CODEX_LOG` (default `$HOME/fake-codex.log`); `codex login status` exits 0, or 1 with `HO_FAKE_CODEX_LOGGED_OUT=1`, and `HO_FAKE_CODEX_SLEEP` makes it slow.

Every test name starts with the requirement ID (for example `H-125`) or the design rule (for example `Rebuild isolation`) that it proves. Helpers are in `tests/lib.sh`: `ok <name>`, `bad <name> <why>`, `assert_eq <name> <expected> <actual>`, `assert_contains <name> <text> <part>` and `assert_exit <name> <code> <cmd...>`.

`tests/fake-bin/gh` is a small stateful GitHub for the ticket queue tests. It keeps each issue as JSON in `$HO_FAKE_GH_DIR/issues/` (default `$HOME/fake-gh`) and logs every call to `$HO_FAKE_GH_DIR/calls.log`. It implements `issue comment --edit-last`, so a regression to editing comments changes the stored comments. Any call it does not know exits 2.

`tests/fake-bin/tmux` and `tests/fake-bin/osascript` are fake terminals for the session and terminal adapter tests. They share one state folder, `$HO_FAKE_TERM_DIR` (default `$HOME/fake-term`), described in `fake-bin/fake-term-lib.sh`. Each opened tab or pane runs its command in the background, so a whole launch and close runs for real. Typed text goes to `<handle>.in`, and every call is logged to `calls.log`. Any call they do not know exits 2, and the fake tmux also refuses any server other than `-L ho-harness`. The fake `claude` stays alive when `HO_FAKE_CLAUDE_HOLD` is `exit` (until it reads `/exit`) or `ignore`, for at most `HO_FAKE_CLAUDE_HOLD_MAX` seconds. While it holds, it acts only when its typed input or the busy mark changed; `HO_FAKE_CLAUDE_STEP_LOG` makes it log each pass (`tick`) and each transcript step (`step`), which `t_fake_claude.sh` counts. `HO_FAKE_CLAUDE_FAIL_MODEL` makes one model fail at start, and `HO_FAKE_CLAUDE_SHOW_ENV` logs one variable. `tests/sessions-setup.sh` is the shared setup for the session tests; every process a test starts is stopped by its exact process ID at the end. `t_deliver.sh` also closes the sessions of each block by their exact PIDs when the next block starts one. `t_run_all.sh` checks `tests/run-all.sh` itself on a copy with fake runners and its own lock path.

For delivery tests, `HO_FAKE_CLAUDE_TRANSCRIPT=1` makes the fake `claude` keep a transcript JSONL under `$HOME/.claude/projects/`. Each whole typed line becomes a user record. While `<handle>.busy` exists in the fake terminal folder, a line is queued instead, and the queue is released when the bytes 0x18 0x13 arrive or the busy file goes. `HO_FAKE_CLAUDE_NOISE=1` adds unrelated records, and `HO_FAKE_CLAUDE_VERSION` sets what `--version` prints. `tests/fake-bin/fake-msg` stands in for a message command between sessions (`HO_FAKE_MSG_MODE`: `deliver`, `noise`, `other`, `silent` or `fail`). The fake terminals keep control bytes as `<0xNN>` in `<handle>.in`. The screens the delivery tests show are fixture files in `tests/fixtures/screens/`.

`tests/fixtures/screen/` holds one saved screen capture per file for the screen-text tests. `tests/fixtures/screen/README.md` says what each file must produce and where the files come from. A test compares only the class word a file produces, never the file's text.
