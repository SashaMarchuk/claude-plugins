Write the plan for ticket @TICKET_ID@ before any code changes.

1. Name the files to change and the behaviour that changes in each.
2. Split the work into small tasks. Each task ends with a check you can run.
3. Map every acceptance check of the ticket to the task and the test that proves it.
4. Name what is out of scope, and the risks, with how you will detect each one.
5. Write the plan to a file in the repository's planning folder, or to the step result if
   the repository has none, and commit it if the folder is tracked.

Result: `pass` when every acceptance check has a task and a test. Change no product code
in this step.
