# Раунд 2 — пропозиції, а не питання

Це те, на що ресерч уже дає чітку відповідь. Кожен пункт — **пропозиція, яку ти можеш відхилити**, а
не рішення, яке хтось прийняв за тебе. Читати не обов'язково перед сесією: якщо мовчиш — вважаємо, що
не заперечуєш, і це можна відкотити будь-коли.

Джерела: `research/GAP-MAP.md` §7, `research/architecture/BUILD-PLAN.md` §2–§3,
`research/platforms/ADAPTER-CONTRACT.md`.

| # | Пропозиція | Чому саме так |
|---|---|---|
| П-01 | **Реєстр власності.** Кожна сесія, ворктрі, гілка, контейнер і сервіс записуються в журнал рану **до** того, як їх створено; ран діє тільки на те, що сам записав. | Це прямий фікс обох задокументованих інцидентів: знищений стек і вбита чужа лінія. Нічого з твоїх рішень не порушує. |
| П-02 | **Ніколи не розгалужуватись на код виходу агента.** Aider повертає 0 навіть після помилки; вердикт береться з нормалізованої події, не з `$?`. | Перевірено на платформах. |
| П-03 | **Два журнали з різною довірою:** що агент *збирався* зробити (його слова) і що *сталося* (перевірено ззовні). | «Готово» від виконавця і доведене «готово» — різні об'єкти; змішування їх коштувало п'яти фаз без перевірки. |
| П-04 | **Один словник подій для всіх платформ:** `turn_started / tool_call / waiting_on_human / compacted / turn_completed / failed`. | П'ятнадцять платформ пишуть транскрипти в п'яти різних форматах; без нормалізації зміна схеми в одній ламає цикл для всіх. |
| П-05 | **Ключ обліку — `ticket_id`**, а `(платформа, акаунт, session_id)` — список, а не поле. | Компакт через «закрити й відкрити нову» перетворює один тікет на ланцюжок сесій; на Droid після компакту взагалі новий id. |
| П-06 | **`orchestrator:status` — звичайний скрипт, не скіл.** | Твоє «мінімальна кількість аутпуту»: статус не має коштувати виклику моделі. |
| П-07 | **Файл заборон, контрольний файл і канал питань резолвляться в абсолютний шлях головного чекауту**, однаково з будь-якого ворктрі. | Файл питань уже роздвоювався на годину. |
| П-08 | **Зміни у файлі ловити хешем вмісту плюс `stat -f '%Fm'` (наносекунди APFS)**, не `mtime` у секундах. | Два записи в одну секунду не видно; перезапис тим самим вмістом рухає `mtime`. Ти сам казав «можливо, по даті» — це виявилось ненадійним. |
| П-09 | **Один писар на файл замість замків.** | Простіше й надійніше, ніж блокування; збігається з тим, як у тебе вже працював канал питань. |
| П-10 | **Канал питань за замовчуванням має форму твоєї власної практики** з <work-project>. | Це єдине рішення в усій сесії, про яке ти сказав «в мене так було» — перевірене тобою, а не вигадане. |
| П-11 | **`TONE.md` засівається з цього ж транскрипта** — п'ять твоїх рішень уже готові: новий тікет замість переробки, три падіння, чекати відповіді, правила репозиторію головніші, дешева модель для спостереження. | Інакше перша ніч працює з порожнім файлом правил. |
| П-12 | **Префлайт не дає роботу лінії, яку сьогодні не перевірено**, і перевіряє акаунт **після** запуску сесії, а не до. | Ліміт читався як «невідомо» цілими ранами; ключ Xiaomi у тебе зараз мертвий (401), Copilot каже `no_access`. |
| П-13 | **Порядок адаптерів: Claude Code → Codex → провайдерна лінія (GLM або DeepSeek за тим самим драйвером).** | Codex — єдиний другий tier-1 і доводить, що інтерфейс не заточений під Claude; провайдерна лінія коштує три змінні оточення. |
| П-14 | **`acpx` вимкнений до одного експерименту:** підняти сесію й перевірити, чи бачить вона `/gsd:execute-phase`. Якщо ні — вся ідея не має сенсу. | Перевірка показала, що за замовчуванням він **не вантажить твої користувацькі налаштування** — а там живуть GSD, плагіни, хуки й дозволи. |
